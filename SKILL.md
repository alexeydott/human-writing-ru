# Живое русское письмо

Цель — точный, естественный и уместный русский текст, а не имитация «человечности» через ошибки, жаргон или случайную разговорность.

## 1. Определи условия задачи

Перед работой зафиксируй пять осей.

1. **Операция** — новый текст / корректура / лёгкая редактура / глубокая переработка / адаптация / текст для произнесения.
2. **Происхождение** — исходно русский / неродной русский / переводной русский / неизвестно. Не угадывай происхождение по одному «странному» обороту; используй эту ось, когда оно известно из запроса или материала.
3. **Отношение к реальности** — фактический / художественный / смешанный.
4. **Канал и регистр** — личное сообщение, статья, соцсеть, деловая переписка, официальный документ, техническая документация, публичная речь, художественный текст и т. п.
5. **Аудитория** — предметная подготовка, возрастная/учебная задача и требования доступности, только если они известны и действительно влияют на текст.

Не выводи стиль человека из пола, возраста, региона, профессии или другой демографии. Такие признаки могут использоваться для исследования корпуса, но не как инструкция «как должен говорить такой человек».

## 2. Загружай только нужные references

- готовый текст пользователя → `references/editing.md`;
- нейтральная проза, статья, блог, длинный ответ → `references/russian-prose.md`;
- фактический материал → `references/reality.md`;
- техническая инструкция/API/руководство → `references/technical-writing.md`;
- техническое задание / спецификация требований / SRS → `references/technical-specification.md`;
- продуктовый/customer case → `references/product-case.md`;
- личное портфолио/проектная ретроспектива → `references/portfolio.md`;
- ИИ-/агентная функция или LLM-пайплайн → `references/ai-feature.md`;
- устная подача → `references/oral-speech.md`;
- художественная проза/диалог → `references/fiction.md`;
- конкретная форма публикации → `references/formats.md`;
- неродной или учебный русский → `references/non-native-russian.md`;
- русский текст, полученный переводом → `references/translated-russian.md`;
- упрощение под конкретного читателя / когнитивная доступность → `references/audience-accessibility.md`;
- разговорная, региональная или платформенная вариативность → `references/language-variation.md`;
- публикационная форма, `ё`, кавычки, прямая речь → `references/orthotypography.md`;
- признаки шаблонного ИИ-письма / humanization-pass → `references/ai-writing-patterns.md`;
- после черновика → `references/revision.md`.

Не загружай весь набор сразу. Если задача сочетает несколько условий, загрузи только пересекающиеся ветки.

## 3. Неподвижные границы

### Факты и опыт

- Не придумывай пользовательский опыт, реальные события, цифры, цитаты, мотивы и наблюдения.
- Заявление компании или участника не превращай в независимый факт.
- Хронология не доказывает причинность.
- Не усиливай степень уверенности при редактуре: «может» не становится «точно», прототип не становится запуском.
- Точную цитату не переписывай ради красоты; при необходимости переходи к пересказу с атрибуцией.

### Авторский голос

- Масштаб вмешательства соответствует запросу.
- Не выравнивай любой исходник под одну модель журнальной прозы.
- Сохраняй намеренный ритм, терминологию, первое лицо, характерную степень категоричности и допустимую разговорность, если пользователь не просит изменить их.

### Русская норма и стиль

- Не навязывай английский SVO-порядок.
- Не запрещай тире, двоеточие, «не X, а Y», причастия, пассив или длинные предложения как классы.
- Различай нормативность, понятность, стилистическую уместность и индивидуальный голос: это разные критерии.
- Точный термин можно повторять; не создавай искусственную вариативность синонимами.

### Вариативность

Нестандартная разговорная, региональная, профессиональная или платформенная форма не является автоматически ошибкой. Исправляй её до литературной нормы только если этого требует задача, жанр или пользователь.

## 3.1. Дополнительный humanization-pass

Если пользователь явно просит убрать шаблонность ИИ-текста либо глубокая редактура выявляет несколько характерных шаблонов одновременно, загрузи `references/ai-writing-patterns.md`. Не используй этот reference как детектор авторства и не переписывай текст только ради обхода детекторов.

Ключевой порядок: сначала сохранить факты, обязательства и голос; затем убрать пустую риторику, фиктивные возражения/альтернативы, мета-анонсы, рекламные усилители и другие конструкции, которые не добавляют содержания. Один признак без контекста не является основанием для правки.

## 4. Материал раньше объёма

Для фактического текста внутренне перечисли опоры: факты, действия, числа с контекстом, источники, этапы, примеры, ограничения, решения и последствия.

Не используй формулу «N фактов на N слов». Каждый крупный фрагмент должен добавлять содержание. Если материала не хватает: исследуй доступное; запроси только действительно недостающий личный факт; либо сузь объём. Не создавай «типичного пользователя» и точные сцены вместо данных.

## 5. Разные цели редактирования не смешивать

- **Грамматичность**: согласование, управление, морфология, синтаксис, пунктуация.
- **Естественность**: коллокации, порядок информации, неудачные кальки, избыточная формальность.
- **Ясность**: читатель понимает действия, условия, референты и термины.
- **Доступность**: текст адаптирован под конкретные возможности аудитории.
- **Голос**: сохраняется индивидуальная манера автора.

Улучшение одного критерия не оправдывает автоматическое ухудшение другого.

## 6. Анализатор

`check_prose_ru.py` — редакторский линтер, не детектор ИИ и не грамматический корректор.

```bash
python3 scripts/check_prose_ru.py --mode prose draft.md
python3 scripts/check_prose_ru.py --mode oral speech.md
python3 scripts/check_prose_ru.py --mode product case.md
python3 scripts/check_prose_ru.py --mode technical manual.md
python3 scripts/check_prose_ru.py --mode official letter.md
```

По умолчанию дословные цитаты исключаются из стилевых частот. Для авторского диалога можно использовать `--include-quotes`.

Для ТЗ добавлен отдельный requirements-checker, который **не заменяет** общий технический линтер:

```bash
python3 scripts/check_tz_ru.py --profile generic spec.md
python3 scripts/check_tz_ru.py --profile gost34 spec.md
python3 scripts/check_tz_ru.py --profile gost19 spec.md
```

`generic` проверяет формулировки требований без заявления о соответствии ГОСТ. `gost34` и `gost19` дополнительно проверяют наличие структурных разделов соответствующих стандартов. Смысловые находки не исправляются автоматически: безопасный autofix ограничен пробельной нормализацией через `--safe-normalize-output`. Правила и сообщения локализованы на русский в `profiles/tz-rules.ru.json`; профили находятся в `profiles/tz-profiles.json`.

После редактуры фактического текста можно отдельно запустить `scripts/check_edit_integrity.py source.txt edited.txt`. Это страховочная проверка чисел, единиц измерения, дат, ссылок, модальности, отрицания, условий, атрибуции, цитат и консервативных entity-like изменений; отсутствие находок не доказывает семантическую эквивалентность.

Текущий профиль — **real-corpus alert policy 1.5.0**, а не языковая норма. Для исследования доступны `--features-only`, `scripts/extract_corpus_features.py` и `scripts/calibrate_profiles.py`. Частоты тире и двоеточий сохраняются как признаки, но пользовательские предупреждения по ним по умолчанию отключены: pilot benchmark не подтвердил их редакторскую пользу. Лексический `hype`-сигнал требует серии совпадений, а в `technical` и `official` отключён. Любой кандидатный порог после корпусной калибровки всё равно должен пройти negative controls и отложенные evals. В ablation 1.4 сигналы `road-sign-density`, `sentence-uniformity`, `long-sentence`, `one-sentence-paragraphs` и `context-jargon-density` были проверены в режиме old → candidate → off, но выборка не достигла freeze gate, поэтому активные значения сохранились до полного внешнего held-out v3 (прогон `data/heldout-work-policy-1.6`, 911 документов, слепая разметка 217 natural alerts). По его итогам применена политика 1.5.0: `long-sentence` отключён для `prose`/`product`/`official` (actionable-precision ≤0.25), порог `one-sentence-paragraphs` для `product` — 0.90674 (removed-алерты 100% non_actionable), `long-sentence` на `oral` сохранён (precision 0.263 > 0.25), остальные пары — keep_old. Воспроизводимый исторический runner 1.4: `scripts/ablate_signals.py`. Для новых решений о порогах используй decision protocol v3 `scripts/ablate_signals_v3.py` + `benchmark/ablation/spec-v3.json`: строки, связанные любым известным author/split/source-document/independence ограничением, остаются в одном split-component; candidate выводится только на calibration и проверяется на untouched validation; source diversity контролируется и по числу документов, и по объёму слов; неизвестный provenance не улучшает diversity; уменьшение числа предупреждений без natural-alert adjudication не считается доказательством пользы. Сетевой orchestration обязан проходить через `scripts/run_external_heldout_gate.py` и не использует исторический runner для новых решений.

Не используй линтер как обязательный валидатор поэзии, художественного диалога, неродного русского или переводного текста: для этих условий у него нет достаточной языковой модели.

## 7. Оценка результата

Для редактуры не сравнивай результат с одним «идеальным» эталоном по строкам. Проверяй независимо:

- сохранены ли смысл и факты;
- не усилена ли степень уверенности;
- исправлены ли реальные ошибки;
- соответствует ли регистр задаче;
- сохранён ли голос в пределах запроса;
- добавляет ли каждый крупный фрагмент содержание;
- понятны ли референты и причинные связи.

Для сравнения версий Skill используй несколько запусков одного eval, предыдущую версию как baseline и слепое попарное сравнение. Детерминированный линтер сравнивай отдельно от генеративной части Skill: улучшение архитектуры Skill не считается доказанным улучшением линтера. Структура данных описана в `evals/README.md`, `DATA_PLAN.md` и `benchmark/METHODOLOGY.md`.

## 8. Приоритет при конфликте

1. Явный запрос пользователя и ограничения исходника.
2. Фактическая точность и честные границы опыта/цитат.
3. Нормы русского языка.
4. Специализированный reference текущего условия.
5. Общий процесс Skill.
6. Эвристики автоматического линтера.

Если пользователь просит только готовый текст, не показывай внутренние проверки.
