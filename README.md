# human-writing-ru 1.9.0-beta.5

> Версия пакета: **1.9.0-beta.5**. Замороженная лингвистическая политика и правила линтера — **1.5.0** (применена по итогам внешнего held-out v3); эти номера намеренно разделены.

human-writing-ru — русская адаптация [Human Writing](https://github.com/KKKKhazix/human-writing): пакет Agent Skill для LLM, позволяющий создавать, редактировать и адаптировать русские тексты в разных условиях. Навык помогает сохранять факты и авторский голос, выбирать регистр и аудиторию, отличать нормативную правку от стилистической, а также учитывать неродной русский, переводной текст и требования доступности.

## Быстрый старт

```bash
# Установка в каталог навыков агента (корень стабилен как human-writing-ru/)
git clone https://github.com/alexeydott/human-writing-ru.git .claude/skills/human-writing-ru

# Проверка целостности пакета
cd .claude/skills/human-writing-ru && python scripts/validate_skill.py

# Первый прогон детерминированного линтера
python scripts/check_prose_ru.py --mode prose article.md
python scripts/check_prose_ru.py --json --features-only article.md   # признаки без вердикта
```

Основные проверки не требуют сети; Python 3.10+ обязателен, `PyYAML` — для самопроверки.
Подробности: [docs/getting-started.md](docs/getting-started.md).

## Ключевые возможности

- **Пятиосевая модель задачи** — операция × происхождение × фактичность × канал/регистр × аудитория; нет выводов о стиле по демографии.
- **18 веток знаний** с прогрессивным загрузом: редактура, техническое письмо, ТЗ/SRS, устная подача, художественная проза, неродной и переводной русский, доступность, orthotypography, признаки ИИ-письма.
- **Неподвижные границы** — факты и авторский голос имеют приоритет; редакторский проход, а не детектор авторства; одиночные признаки не считаются доказательством.
- **Детерминированный линтер русской прозы** с замороженными порогами 1.5.0 (`profiles/editorial-baseline.json`) и воспроизводимой ablation v3.
- **Интегральность правок** — `check_edit_integrity.py` отслеживает числа, даты, URL, модальность, отрицание, цитаты и conservative-изменения сущностей.
- **TZ-нормализация** — безопасная переработка технических заданий (`check_tz_ru.py`, профили generic/gost34/gost19).
- **Автономная lite-инструкция** — ≤2000 знаков, без программ и локальных файлов (`scripts/build_lite.py`).
- **Воспроизводимый выпуск** — детерминированный ZIP + SHA-256, manifest целостности, frozen-input контроль.

## Недавние изменения

### 1.9.0-beta.5

- Применена лингвистическая политика **1.5.0** по итогам первого полного внешнего held-out v3
  (911 валидированных документов, слепая разметка 217 natural alerts): `long-sentence`
  отключён для prose/product/official, порог `one-sentence-paragraphs` для product
  пересмотрен до 0.90674, `long-sentence` на oral сохранён (подробности — CHANGELOG).
- Полные evidence gates закрыты для всех пяти профилей; протокол held-out v3 описан в
  [docs/data-and-pipeline.md](docs/data-and-pipeline.md), план и итоги — в
  [POLICY_RERUN_PLAN.md](POLICY_RERUN_PLAN.md).

### 1.9.0-beta.4

- Повторно выполнен локальный held-out workflow v3: проверки кода, целостности, манифеста и минимального объёма прошли; активные пороги не менялись — проверки происхождения и разнообразия остаются неполными.
- Усилено получение веб-кейсов: RBC принимает только страницы отдельных материалов, Ruward извлекает содержательные блоки без меню и колонтитула.
- Получение Yandex Cloud Docs устойчиво обрабатывает усечённый ответ GitHub API (обход поддерева `ru/`).
- Краткая инструкция для сетевых диалогов стала автономной: без программ и локальных файлов, ≤2000 знаков (с запасом до 2048), без остаточных англицизмов.

### 1.9.0-beta.3

- Локальные корпуса и результаты workflow сведены в единый gitignored-каталог `data/`; переменная окружения переименована в `HUMAN_WRITING_RU_DATA_DIR`.
- Добавлено руководство `data/README.md`: что скачивается, откуда берутся наборы, какие средства нужны для OCR и как воспроизвести конвейер локально.
- Сборщик релиза без параметров формирует готовый ZIP и SHA-256 в `dist/`, исключая тяжёлые данные.

Полная история версий — в [CHANGELOG.md](CHANGELOG.md).

Большие сторонние корпуса не включаются в выпуск: в пакете схемы, ссылки, хеши, инструменты и

проверяются отдельно и записываются в манифест. Подробности — [docs/data-and-pipeline.md](docs/data-and-pipeline.md),
[DATA_PLAN.md](DATA_PLAN.md), [SOURCES.md](SOURCES.md).

## Ограничения beta

- Внешний held-out v3 выполнен (прогон `heldout-work-policy-1.6`, политика 1.5.0);
  генеративное A/B между версиями Skill ещё не проведено.
- Утверждения о превосходстве генерации не активируются без настоящего A/B
  (протокол — `evals/AB_EVAL_PROTOCOL.md`); новые сигналы — только после собственного
  corpus evidence (ROADMAP §4).
