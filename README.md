# human-writing-ru 1.9.0-beta.4


> Версия пакета: **1.9.0-beta.4**. Замороженная лингвистическая политика и правила линтера остаются **1.4.0**; эти номера намеренно разделены.

Русская адаптация [Human Writing](https://github.com/KKKKhazix/human-writing), ориентированная на генерацию, редактуру и адаптацию русских текстов **в разных условиях**, а не на одну модель «хорошей публицистики».

## Что изменено в 1.9.0-beta.4

- Повторно выполнен локальный held-out workflow v3: проверки кода, целостности, манифеста и минимального объёма корпусов прошли, но активные пороги не менялись, так как проверки происхождения и разнообразия остаются неполными.
- Получение веб-кейсов усилено: RBC принимает только страницы отдельных материалов, а Ruward извлекает содержательные блоки кейса без меню и нижнего колонтитула.
- Получение Yandex Cloud Docs устойчиво обрабатывает усечённый ответ GitHub API: для большого репозитория обходится объявленное поддерево `ru/`.
- `profiles/README.md` описывает актуальный калибровочный цикл v3: раздельные диагностические распределения `profile,channel`, связанный split, ручная разметка естественных срабатываний и запрет на автоматическое изменение профиля.
- Локальные данные и результаты workflow по-прежнему не входят в Git или архив выпуска.

## Что изменено в 1.7.0-beta.2

1. **Упаковка и спецификация:** корень установки стабилен как `human-writing-ru/`; `SKILL.md` использует YAML-заголовок с `license`, `compatibility`, `metadata.version=1.7.0-beta.2` и отдельно `metadata.policy_version=1.4.0`. Самопроверка проверяет имя каталога, разделение версий, ссылки, literal `\n`, контракты реестра и оценочного набора, а также зафиксированные SHA.
2. **Протокол принятия решения v3:** кандидат строится только на компонентах калибровки и оценивается на независимой проверке. Связанный split объединяет известные связи `author`/`split`/`source-document`/`independence`; варианты регистра и пробелов в метках происхождения нормализуются, а непрозрачные ID остаются чувствительными к регистру.
3. **Проверки достаточности доказательств:** кроме 50 документов / 10 000 слов действуют разнообразие профилей, источников, каналов и авторов, а также пригодность/разнообразие сигналов и минимальный split. `unknown`, `n/a` и другие служебные значения не считаются разнообразием; концентрация источника проверяется по документам и объёму слов.
4. **Разметка естественных срабатываний:** `actionable` и `non_actionable` — решающие метки; `uncertain` сохраняется в отчёте, но не улучшает и не ухудшает точность `actionable` и не помогает проверке доказательств. ID аннотаций должны ссылаться на реальную пару документ/сигнал и не конфликтовать.
5. **Целостность получения и проверки:** точное устранение дублей выполняется с областью `(profile, sha256)`, чтобы конфликт маршрутизации между профилями не исчезал до проверяющего этапа. Проверка блокирует одинаковый текст в разных профилях, перенастраивает пути при пользовательском каталоге вывода и создаёт только представительный `manifest.validated.csv`. v3 повторно проверяет SHA файла и точные дубли перед решением.
6. **Сетевой исполнитель:** текущий координатор вызывает только v3, требует чистого результата проверки, использует новый рабочий каталог по умолчанию и разрешает продолжение только явно и только для выбранных ID источников. Источники с `format_unverified` по умолчанию не участвуют в принятии решения.
7. **Достижимость источников и происхождение данных:** набор источников для `technical` дополнен русской документацией Kubernetes; локальные корпуса могут передавать проверенные поля `speaker`/`author`/`split`/границы документов через сопроводительный `manifest.csv`. Duma добавлена как отдельный слой `oral`; XML Путина не получает фиктивного единого автора.
8. **Исправления ошибок выполнения:** исправлен адаптер LJSearch, который после успешной загрузки мог обращаться к неопределённым `profile`/`channel`; регрессионный тест воспроизводит успешный сетевой ответ без реального Интернета.
9. **Целостность правок:** `check_edit_integrity.py` отслеживает числа, даты, валюты, URL, число+единица, модальность, отрицание, условия, attribution, цитаты и консервативные изменения сущностей. URL path/query сохраняют регистр; отсутствие результатов не трактуется как доказательство смысловой эквивалентности.
10. **Генеративное A/B-тестирование:** рабочий каталог фиксирует текущие и предыдущие ID навыка, SHA оценочного набора и копирует входные материалы с SHA. Сводчик по умолчанию требует полную матрицу; неполный диагностический режим не выдаёт непарные итоговые разности и сравнивает только совпадающие `(case, run_index)`.
11. **Что намеренно не изменено:** `check_prose_ru.py`, исторический `ablate_signals.py` и `editorial-baseline.json` остаются побайтно неизменными в рамках замороженной политики 1.4. Новые пороги или утверждения о превосходстве генерации не активируются без внешнего held-out v3 и настоящего A/B-тестирования.

## Калибровка на локальной выборке

Создайте манифест по образцу `data/corpus_manifest.example.csv`, затем:

```bash
python3 scripts/extract_corpus_features.py \
  --manifest data/corpus_manifest.csv \
  --output data/features.csv

python3 scripts/calibrate_profiles.py data/features.csv \
  --group-by channel,target_register \
  --min-docs 20 \
  --min-words-per-doc 100 \
  --output data/distributions.json
```

Для коротких чатов/соцсетей размер документа и группы следует задавать отдельно. Полученные квантили — **описание выборки, не языковая норма**.

## Данные и лицензии

Большие сторонние корпуса не включены в ZIP. В выпуске находятся только схемы,
маленькие собственные примеры для оценочного набора, инструменты извлечения признаков
и ссылки. Для каждого внешнего набора нужно отдельно проверить условия использования
и записать их в манифесте. См. `DATA_PLAN.md` и `SOURCES.md`.

## Ограничения beta

- выполнен только малый пилот на реальном корпусе детерминированного линтера; он не является репрезентативной корпусной калибровкой;
- генеративное A/B-тестирование между версиями Skill ещё не проведено: пилот сравнивает только `check_prose_ru.py`;
- GEC на уровне правил и кореференция представлены планом/оценочными наборами, а не встроенным тяжёлым NLP-анализом;
- незакрытые измерения видны через `scripts/audit_eval_coverage.py`.
