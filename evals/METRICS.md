# Метрики и критерии оценки

Не существует одной метрики «качества русского текста». Оценивай задачу по независимым критериям.

## Активация Skill

- trigger recall на `should_trigger`;
- false-trigger rate на near-miss negative;
- разброс по повторным запускам;
- отдельно train и validation split.

## Фактическая целостность

- новые неподтверждённые фактические утверждения;
- изменение чисел, дат и именованных сущностей;
- потеря атрибуции;
- изменение модальности (`может` → `точно`), отрицания, условий и причинности;
- вымышленный личный опыт.

Это важнее стилевого score.

## Редактура

- grammatical correctness по категориям;
- meaning preservation;
- register fit;
- voice preservation;
- edit minimality относительно заданной глубины правки;
- over-edit rate: доля корректных/функциональных конструкций, которые были изменены без необходимости.

Edit distance можно использовать как диагностический показатель минимальности, но не как самостоятельную метрику качества.

## Переводной русский

Оценивать двумя независимыми осями:
1. естественность русского;
2. сохранение смысла оригинала/русского черновика.

Если известен исходный язык, результаты группировать по нему или по языковой близости; не превращать статистические свойства translationese в список запретов.

## Неродной русский

- precision/recall по типам реальных ошибок;
- unnecessary edit rate на нормативных фрагментах;
- сохранение содержания и авторской структуры;
- качество объяснения, если пользователь учится.

Общий GEC-score обязательно дополнять rule-level отчётом.

## Доступность

Проверять не «стало ли короче», а:
- сохранены ли обязательные условия;
- объяснены ли незнакомые термины/сокращения;
- явны ли действия и последовательность;
- соответствует ли версия заявленной аудитории;
- нет ли неоправданной инфантилизации.

## Стиль

Стиль и «естественность» лучше сравнивать слепо попарно на нескольких независимых выводах. Не использовать детектор AI-generated text как ground truth.

## Автоматический линтер

Для `check_prose_ru.py` измерять:
- **alert burden**: findings/1000 слов и долю документов с сигналами — это диагностическая нагрузка, не false-positive rate;
- false positive rate только на вручную размеченных `false_positive_cases.json` или эквивалентном контрольном наборе;
- warning precision по ручной разметке;
- распределение кодов по профилям/жанрам;
- сохранение целевых категорий на positive controls;
- стабильность порогов при изменении состава корпуса.

Нельзя считать уменьшение числа предупреждений самостоятельным улучшением текста. Сигнал удаляется/ослабляется только если его шум подтверждён контекстом и нужная диагностическая категория не теряется на positive controls.
