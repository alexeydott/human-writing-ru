# Pass 17 — false-positive pruning

После первого варианта эвристики сужены: союз «и» сам по себе не считается составным требованием; проверяемость не требует числа для каждого функционального требования; security warning подавляется при наличии наблюдаемого/числового критерия; неоднозначные местоимения проверяются только внутри requirement-like строк; ГОСТ-разделы не проверяются в generic profile.

Negative/positive controls: `evals/tz_rule_cases.json`, `tests/test_tz_rule_cases.py`.

На одном реальном крупном ТЗ (1 337 279 байт; исходник не перераспространяется) последовательный pruning изменил агрегированное число находок `288 → 26 → 19 → 16`. Это показатель уменьшения alert burden на конкретном документе, **не** оценка precision/recall. SHA и агрегаты сохранены в `quality/TZ_REALWORLD_REGRESSION.json`.
