# A/B generative eval, итерация 1: human-writing-ru 1.9.0-beta.5 (policy 1.5.0) против 1.9.0-beta.4 (policy 1.4.0) и без Skill

Дата: 2026-08-28. Протокол: `evals/AB_EVAL_PROTOCOL.md`. Рабочий каталог: `data/ab-eval/iteration-1/` (локальный, gitignored).

## Методика

- **Arms** (зафиксированы в `run-manifest.json`):
  - `current_skill` = `human-writing-ru@1.9.0-beta.5` (policy 1.5.0);
  - `previous_skill` = `human-writing-ru@1.9.0-beta.4` (policy 1.4.0);
  - `without_skill` = модель без Skill.
- **Набор:** 28 кейсов `evals/evals.json` (SHA-256 `145d68112ce2e0b3f72d7d948c500ba0980909daed6bcfb3060eac485692ff78`, зафиксирован в манифесте). 3 arms × 5 независимых прогонных запусков в чистом контексте = **420 generation runs** (seed 20260827).
- **Судейство:** **420 blind pairwise** сравнений (3 на каждый case/run: cur×prev, cur×none, prev×none; направление сторон зафиксировано seed). Судья — LLM в чистом контексте, батчами по кейсам; судье не сообщается, какая сторона какая (ограничение — см. «Ограничения», п. 3).
- **Per-run grading:** для каждого run ассерции проверялись в двух независимых pairwise-вердиктах; `grading.json` выведен консервативно: ассерция `passed` только если **оба** вердикта дали `pass`. Рассогласования между двумя вердиктами: 24 из ~1512 ассерционных наблюдений (~1.6%) — уровень шума судей.
- Инфраструктурные сбои: 5 перезапусков judge-батчей (таймауты стрима, переполнение контекста) — все восполнены, пропущенных вердиктов нет. 20 вердиктов завершены в предшествующей сессии, остальные 400 — в этой; поле `case_id` во всех 420 вердиктах нормализовано к pairing_id (метаданные).

## Наблюдения

1. **Skill (обе версии) стабильно впереди базового без Skill** по preference (43.6% против 30.7%), factual/modality scores и assertion pass rate; преимущество по preference пограничное (p≈0.095/0.129, не <0.05).
2. **current (1.5.0) и previous (1.4.0) статистически неразличимы** (p=0.505). current чуть лучше по safety-осям (factual +0.10, modality +0.09) и чуть хуже по over_editing (+0.04) и итоговому preference.
3. **Локальная over-editing-тенденция current в `quotes-code`** (0:5 против without, 1:2 против previous): императив авторского текста «Затем выполните … и откройте» перестраивается в косвенную модальность «Затем в тексте предлагается выполнить … и открыть» — лишняя трансформация без редакторской необходимости (цитата/команда/URL при этом сохраняются дословно, все ассерции pass).
4. `without_skill` систематически дополняет `product-story` вымышленными цифрами и деталями (5:0 поражение против current).
5. Поведение при отсутствии входного текста различается по arms (refusal-подобные ответы в prompt-only кейсах: cur 32/110, prev 36/110, none 28/110, эвристика); часть прогонов выдумывает исходный материал (см. «Ограничения», п. 1).

## Ограничения

1. **Деградация prompt-only кейсов:** только 6 из 28 кейсов имеют входные файлы; в «редактурных» prompt-only кейсах (edit-preserve-voice, high-stakes-health-rewrite, l2-known-l1, unknown-origin, social-platform-voice и др.) задача вырождается в «отказ/выдумка при отсутствии текста», а не в редактуру. Сигнал по качеству редактуры несёт в основном подмножество из 6 кейсов с файлами и generation-кейсы.
2. **Судье не предоставлялись входные файлы** (pairing-промпт содержит только задачу, ассерции и пути к вариантам): ассерции, требующие сверки с исходником («URL сохранены дословно», «смысл исходного сохранён»), судьи корректно отмечали `uncertain`.
3. **Слабая слепо́та:** имена каталогов arms видны в путях файлов судьи; судья инструктировался игнорировать их, независимой проверки соблюдения не было.
4. Судейство велось батчами по кейсу в одном чистом контексте: тексты одного run повторяются в двух pairing батча.
5. `previous_skill_id` в `evals.json` (1.6.1-beta.1) устарел; фактически свершён `1.9.0-beta.4` (манифест — авторитетен).

## Вывод по протоколу (`AB_EVAL_PROTOCOL.md`)

- Не хуже factual/meaning safety — **да** (high-stakes 4.0/4.0 у всех arms; cur−prev factual +0.10; фабрикаций нет).
- Trigger precision/recall на validation split — вне scope A/B (сигналы линтера); обеспечено held-out v3, на котором основана policy 1.5.0.
- Устойчивое преимущество current над previous на целевых задачах — **нет** (p=0.505; preference даже чуть в пользу previous).
- Новый класс систематического over-edit — **нет** (один локальный паттерн на quotes-code, не распространяется на другие жанры).
- Регрессия high-stakes — **нет**.

**Итог:** A/B не подтверждает 1.9.0-beta.5 как улучшение над 1.9.0-beta.4 (различия в шуме), но и не находит регрессий; policy 1.5.0 остаётся обоснованной независимыми данными held-out v3. Утверждение «Skill лучше отсутствия Skill» — поддерживается по направлению (preference, safety-оси, pass rate) на уровне пограничной значимости; формулируется как положительный локальный результат, а не как сильное общее превосходство.
